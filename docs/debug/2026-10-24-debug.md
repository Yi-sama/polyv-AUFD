# Backend Debug Notes - 2026-10-24

## Inherited TLS Setting

- Baseline `npm test` initially passed 15/21, failed six Polyv tests with
  `TLS_DISABLED`. The shell inherited `NODE_TLS_REJECT_UNAUTHORIZED=0`.
- Root cause: existing Polyv code deliberately refuses unsafe TLS configuration,
  including when fetch is mocked. This was not an API regression.
- Verified resolution: set the variable to `1` only in the subprocess before
  tests, live account diagnostic and backend startup. Baseline then passed 21/21;
  final expanded suite passed 32/32. No global environment changes.
- Reviewer's first offline probe hit the same guard and passed after the same
  process-local setting. A browser CLI invocation also warned about the inherited
  setting; subsequent CLI commands explicitly enabled verification.

## Independent Review Disposition

- Review concern: passing a VID using the upstream `title` parameter might miss
  videos whose human-readable title differs.
- Checked official source:
  https://help.polyv.net/vod/api/video_management/search/search_video/
- Its request table explicitly defines `title` as fuzzy title/VID search.
  The reported reproduction used a title-only mock, which does not model this
  upstream contract. No runtime defect was established by that reproduction.
- Kept exact VID comparison after the upstream fuzzy search; added a test that
  checks the outgoing title parameter equals the selected VID.
- Initially, live account search succeeded but returned zero videos. This was a
  historical data blocker, not a search-code defect.
- On 2026-10-24, after Claude's successful public-video import, an exact lookup
  of `0cf5cbb2f905e3ac62e97c0c16d1de4e_0` returned published status 61.
  Its saved cover is local WebP; actual anonymous playback and a 2-second seek
  were independently verified in the browser. The empty-library blocker is closed.
- The diagnostic still reports playbackVerified=false by design because it only
  checks the API. Browser evidence is recorded separately in
  `docs/progress/2026-10-24-backend-verification.md`.
