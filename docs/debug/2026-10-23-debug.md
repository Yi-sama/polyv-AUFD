# 2026-10-23 Backend Debug Notes

## Multipart Upload Rejected

- Baseline: initial suite 15/17 passed; valid PNG multipart returned 400.
- Cause: Busboy emits `partsLimit` when the first part reaches a limit of 1.
- Fix: allow parser to encounter a second part while enforcing one file, no fields;
  an extra part still rejects. Inclusive byte-size limit adjusted at the same boundary.
- Verified: successful multipart and legacy uploads, duplicate-file rejection,
  corrupt image and oversize rejection.

## Host Test Did Not Exercise The Guard

- Symptom: a test using fetch with a different Host unexpectedly returned 200.
- Controlled probe showed fetch transmitted the actual localhost Host, whereas
  `http.get` transmitted `evil.example`.
- Changed the test transport, not the access guard. Actual foreign Host returns 403.

## Independent Review Findings

- Env precedence: local template empty values blocked later `loadEnvFile` settings.
  Replaced implicit environment mutation with native `parseEnv` and explicit merge:
  local defaults, external file, shell overrides.
- Legacy upload: repeated-group regex exhausted V8's regex stack for a valid
  approximately 6.76 MB PNG. HTTP returned 500. Canonical base64 checking now
  avoids nested repetition; the same upload returns 201 with 1500 x 1500 dimensions.
- Added two regression tests. Final suite is 19/19 passing.

## Dependency Audit

- First audit of sharp 0.34.x reported one high-severity dependency item.
- Upgraded to sharp 0.35.5 as recommended by the live npm audit response.
- Final audit reports no known vulnerabilities; all tests rerun on the new version.
- Installation used strict TLS throughout; no global TLS or proxy setting changed.

## Resume: Backend Connection Refused

- HTTP probes for health and portfolio failed; a detailed probe returned
  `ECONNREFUSED`. Listener enumeration showed only frontend ports 5173 and 5174.
- Original backend PID 26016 was absent. Existing stdout had a startup message
  and stderr was empty, so an exit cause was not established.
- Started the same backend as a hidden local process (PID 11452), preserving data.
- Direct and both proxied reads returned 200. Proxied conflict saves returned 409;
  complete document equality before/after confirmed no persisted changes.
- This restores availability but does not claim to fix an unknown process-lifecycle
  root cause. No automatic restart service or global environment setting was added.

## Polyv Empty Transcode Metadata

- Correction: the initial analysis overlooked the surrounding ternary operator.
  With an empty array, the condition is falsy and the original expression already
  returned `null`, not numeric `0`.
- A direct Node assertion evaluated both expressions and returned
  `{original:null, explicit:null, behaviorChanged:false}`.
- The explicit `streams.length > 0` check and new test improve readability and
  coverage, but must not be reported as fixing an observed bug.
