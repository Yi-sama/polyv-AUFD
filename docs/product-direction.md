## 1. 之前理解错在哪里

现在的 `frontend` 被做成了**“刘润森的个人作品集网站”**：页头是个人名字、“A PERSONAL COLLECTION”、“精选 / 全部作品 / 关于”，编辑页也只编辑这一个人。示例专题只存在于前端（`demo-content.ts`），不经过后端。

**这是偏题。** 刘润森不是网站的主人，只是平台上的一位大咖。

## 2. 正确的产品定义

**AUFD 是一个收录多位大咖的作品集平台。**

- 痛点：保利威有很多大咖（在保利威做直播、讲课的讲师、主播、嘉宾），他们有自己的海报、优秀照片、视频，却没有一个好的作品集来展示自己。
- 平台做三件事：
  1. **大咖在站内编辑自己的主页**：资料、海报、照片、视频（视频来自保利威）。
  2. **分享**：每位大咖有独立链接，可以发给合作方、主办方、学员。
  3. **外人浏览**：任何人不登录就能逛平台，查看各位大咖的信息和作品。
- 这是一个**最基础的作品集平台 Demo**，要求不高，但结构要对、流程要通。

## 3. 角色与权限（硬性要求）

| 角色 | 能做什么 |
|---|---|
| 访客（未登录） | 浏览平台首页、所有大咖主页、作品详情；复制分享链接 |
| 大咖（已登录） | 以上全部，加上**只能编辑自己的主页**：改资料、增删改作品、上传图片、从保利威选视频、标精彩片段 |

- **每位大咖只能改自己的页面，这是必然要求，必须由后端强制**，不能只靠前端隐藏按钮。
- Demo 级认证即可：账号（slug）+ 密码登录；密码在服务端加盐哈希（Node 自带 `crypto.scrypt`）；登录后发会话 token（HttpOnly Cookie 或 Bearer 均可），服务端校验“token 所属 slug === 被修改的 slug”，否则返回 403。
- 支持**入驻**：新大咖填写标识（slug）、姓名、密码，创建一个空主页，然后进入编辑。
- 不做：找回密码、第三方登录、管理员后台、邮箱验证。

## 4. 页面结构（frontend 需要按此重组）

| 路由 | 页面 | 内容 |
|---|---|---|
| `/` | 平台首页 | 平台名与一句话定位（面向“发现大咖”，不是某个人的自我介绍）；大咖列表（头像、姓名、头衔、领域标签、一两件代表作缩略）；按姓名/领域搜索或筛选；“入驻 / 登录”入口 |
| `/:slug` | 大咖主页 | 资料头部（头像、姓名、头衔、领域、简介、联系方式）；作品墙（按类型筛选：海报/照片/视频）；“分享”按钮（复制链接）；本人登录时显示“编辑我的主页” |
| `/:slug/works/:workId` | 作品详情 | 大图/多图浏览与放大；视频作品用保利威播放器播放，精彩片段点击跳转；上一件/下一件；返回时保留滚动位置 |
| `/join` | 入驻 | 创建账号和空主页 |
| `/login` | 登录 | |
| `/studio` | 编辑我的主页 | 只编辑当前登录的这位大咖；保存后可直接打开自己的公开主页 |

- 页面上所有“我的作品集”式文案都要换成平台视角。
- 现有已做好的能力尽量复用：作品详情、图片放大、保利威播放器组件、精彩片段、筛选、409 冲突处理、Studio 的上传和保存逻辑。
- 视觉不追求复杂，保证：作品是主角、手机上能正常浏览、加载和错误状态清楚。

## 5. 一位大咖展示哪些信息（Demo 级，够用即可）

```ts
interface Creator {
  slug: string;            // /^[a-z0-9-]{2,40}$/，同时是登录账号和主页 URL
  revision: number;
  profile: {
    name: string;          // 姓名
    alias: string;         // 英文名，可空
    title: string;         // 头衔，如“直播运营讲师”（可沿用原 role 字段）
    tags: string[];        // 擅长领域，≤5 个
    bio: string;           // 一句话简介
    about: string;         // 详细介绍，可空
    contact: string;       // 公开联系方式（邮箱或链接），可空
    avatar: string;
    cover: string;         // 可空，主页头图
    updatedAt: string;
  };
  works: Work[];           // 沿用现有 Work 结构（poster/photo/video、images、videoId、highlights、isDemo）
  isSample: boolean;       // 示例大咖，服务端字段
}
```

字段名可以按现有代码调整，但含义要覆盖上表。

## 6. 示例大咖与素材

只有一位大咖撑不起“平台”，需要 **3–5 位示例大咖**：

- **刘润森（Yisama）**：唯一的真实大咖。素材用他的参赛海报（`server/assets/poster.jpg`），头像也可以用海报；简介随意写；视频先占位。
- **其他示例大咖**：用户没有素材，**授权从网上找类似的图片**：
  - 只用允许免费使用的图库（Unsplash、Pexels 等），每张图在 `SOURCES.md` 记录来源链接和作者。
  - 人物和名字都是**虚构的**，主页上明确标注“示例大咖”。不使用真实名人的姓名或照片，也不编造获奖、粉丝数之类的成就。
  - 每位示例大咖：1 个头像、3–6 件作品（海报或照片），领域彼此不同（例如电商直播、职业教育、企业培训、摄影），平台首页才有区分度。
- **示例数据必须进入后端**，作为真实的 Creator 数据存储，和真实大咖走同一套接口。不要再做只存在于前端的展示内容（现有 `demo-content.ts` 的做法要撤掉）。
- 示例大咖也要有可登录的密码，写在本地文档里（不进前端代码），方便演示“只能改自己”。

## 7. 保利威接入（产品核心，不是摆设）

卖点：**大咖的视频本来就在保利威里，作品集不用再上传一遍，直接从保利威选进来。**

- Studio 中“添加视频作品”→ 调 `/api/polyv/videos` 搜索保利威视频库 → 选中后自动带入标题、封面、时长 → 可以加精彩片段（标题 + 秒数）→ 保存。
- 作品详情用保利威 Web 点播播放器播放，精彩片段点击跳转。
- Demo 阶段平台共用一个比赛账号的视频库，这一点要如实说明。正式产品应由每位大咖绑定自己的保利威账号。
- **必须跑通一次真实视频**：比赛账号的视频库目前为空。请往账号里上传至少一个视频（保利威后台手动上传，或调用上传 API/SDK 均可），然后完整验证“搜索 → 选入 → 保存 → 访客页播放 → 精彩片段跳转”。官方示例 VID 只能作为兜底，并保持“官方示例”标注。

## 8. 后端需要的改动（`server/`）

现状：只支持单个作者（`model.mjs` 中 `SLUG = 'liurunsen'`）；编辑靠“本机回环地址 + ADMIN_TOKEN”放行，不区分是哪位大咖。

需要改成：

1. **多大咖存储**：例如 `data/creators/<slug>.json` 每人一个文件，或单文件 map；每位大咖有独立的 revision。账号数据（密码哈希）和公开文档分开存，**公开接口绝不返回密码哈希**。
2. **接口**（命名可调整）：
   - `GET /api/creators?q=&tag=` → 列表（slug、name、alias、title、tags、avatar、一两件代表作、isSample）
   - `GET /api/creators/:slug` → 完整公开文档
   - `POST /api/auth/join` → 入驻（slug 唯一校验）
   - `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`
   - `PUT /api/creators/:slug` → **只有本人可改**，否则 403；revision 冲突返回 409
   - `POST /api/upload` → 需要登录
   - `GET /api/polyv/videos` → 需要登录
   - `GET /api/polyv/play-token?vid=` → 公开，但 VID 必须出现在**某位大咖已保存的作品**中
3. **图片路径校验**：`IMAGE_PATTERN` 目前只允许 `poster.jpg` 和 uploads，要放行示例素材目录（例如 `/assets/samples/...`），或者把示例图片作为上传文件导入。
4. 旧的 `/api/portfolio` 可以删除，也可以保留为刘润森的别名，不强求。
5. 更新测试：至少覆盖“A 不能改 B（403）”“未登录不能改（401）”“本人能改”“入驻 slug 重复”“公开接口不泄露密码哈希”。

安全边界保持原有的克制做法：密钥只在服务端，不进前端；不打印环境变量。

## 13. 前端方向与后端配合（v2.1 新增）

用户已选定前端方向：**「频道」**。保利威是直播/视频平台，所以每位大咖是一个“频道”，平台首页是“节目表”：

- 首页每位大咖一行（频道号、姓名、领域）；鼠标悬停时预览窗轮播他的作品，有视频则播放一个精彩片段。
- 大咖主页是他的频道：顶部“正在播放”代表作，下面是作品单。
- 切换大咖像换台：电脑 ↑/↓，手机上下滑动；另有“随便换台”。
- 动效只做短而有功能的：换台过渡、悬停预览、筛选重排、作品展开/收回；支持减少动态效果。
- 不做 Remotion 片头。

为此，后端请额外提供（字段名可调整，请把最终约定写进 `docs/backend-api.md` 并标注版本）：

1. **频道号**：每位大咖一个服务端分配、稳定不变的整数 `channel`（入驻时递增，从 1 开始；刘润森为 1）。`GET /api/creators` 默认按 `channel` 升序。
2. **列表里带预览素材**：`GET /api/creators` 的每一项除资料外，再带：
   - `worksCount`：作品数（官方示例视频不计入）；
   - `previews`：最多 6 个 `{ workId, type, cover, width, height }`，按作品顺序、优先 `featured`；
   - `previewVideo`：第一件视频作品的 `{ workId, videoId, seconds, isDemo }`（`seconds` 取第一个精彩片段，没有则为 0），没有视频则为 `null`。
   这样首页悬停预览不用逐个请求大咖详情。
3. **筛选**：`GET /api/creators?q=&tag=` 中 `q` 匹配姓名/英文名/头衔，`tag` 精确匹配领域；另提供 `GET /api/tags` 返回全部领域及人数（或在列表响应里带 `tags` 汇总，二选一）。
4. **登录方式**：建议同源 HttpOnly Cookie（`SameSite=Lax`），前端经 Vite 代理访问，`fetch` 带 `credentials: 'include'`。`GET /api/auth/me` 未登录返回 401 或 `{ creator: null }`，请在文档写明是哪种。
5. **示例大咖里至少一位带视频作品**：可以先用官方示例 VID（保持 `isDemo: true` 标注），保证首页悬停预览和换台演示时有视频可播；比赛账号有真实视频后，把刘润森的视频换成真实 VID。
6. **图片尺寸**：所有封面和图片都带宽高（沿用 `media`），前端靠它预留位置、避免跳动。
7. 端口仍为 `127.0.0.1:4317`；`/api`、`/assets`、`/uploads` 路径不变。

完成每一步后，在 `docs/progress/2026-10-24.md` 记一笔接口已就绪的情况，Claude 前端会按文档对接。
